# مناسبتي

تطبيق Flutter عربي لحجوزات المناسبات، اكتشاف مقدمي الخدمات، وإدارة الحسابات.

## الوظائف

- سوق للأفراح يضم القاعات والفنانين والمصورين والتنسيق والخدمات، مع البحث والتصنيف والترتيب.
- صفحات مقدمي الخدمات مع جدول توفر؛ طلبات الحجز تشمل الفترة، الباقة، عدد الضيوف، السعر والعربون.
- نموذج تسعير للمناسبات يدعم الأسعار الموسمية الشاملة ليومي البداية والنهاية، وسعة القاعات، والفترات الصباحية والمسائية واليوم الكامل.
- إدارة أسعار مقدم الخدمة والعربون والسعة وأسعار الباقات وإضافة/حذف الفترات الموسمية من ملفه.
- تسجيل الدخول بالبريد الإلكتروني وكلمة المرور من Supabase Auth، مع استمرار التصفح كزائر.
- تسجيل مقدم الخدمة مع صور الهوية وإثبات النشاط في مخزن خاص، وحالة تحقق يراجعها مسؤول مخول.
- لوحة إدارة سحابية لمراجعة المزودين والوثائق والحجوزات والحركات المالية والبلاغات.
- تخزين محلي للحجوزات والحسابات في وضع العرض دون إعداد Supabase.

الرسائل والإشعارات داخل التطبيق ما زالت واجهات تجريبية. لا توجد بوابة دفع أو تحويلات مالية فعلية، ولا ينبغي اعتبار الحركات المالية التجريبية نظاماً محاسبياً معتمداً.

## التشغيل

```shell
flutter pub get
flutter run
```

يتطلب بناء Android إصدار API 19 أو أحدث.

إنشاء نسخة ويب:

```shell
flutter build web
```

## إعداد Supabase

1. أنشئ مشروع Supabase جديداً وفعّل تسجيل الدخول بالبريد الإلكتروني في إعدادات Authentication.
2. نفّذ [supabase_schema.sql](./supabase_schema.sql) في SQL Editor. يحتفظ المخطط بوثائق التحقق في bucket خاص مع سياسات RLS، ويحسب الأسعار ويتحقق من تعارض المواعيد في الخادم.
3. **قبل تنفيذ المخطط على قاعدة تحتوي بيانات سابقة، خذ نسخة احتياطية.** آخر سطر في المخطط يحذف جدول حجوزات الشاليهات القديم صراحةً لأنه لا يطابق حجوزات المناسبات.
4. أضف حساب المسؤول عبر SQL Editor بعد تسجيل دخوله مرة واحدة، باستخدام معرّف حسابه:

   ```sql
   update public.profiles
   set role = 'admin'
   where id = 'AUTH_USER_UUID';
   ```

5. إذا كنت قد شغّلت المخطط قبل تحديث تسجيل الدخول بالبريد أو Google، نفّذ أو أعد تنفيذ
   [supabase_email_auth_migration.sql](./supabase_email_auth_migration.sql) في SQL Editor.
   في مشاريع Supabase الجديدة، أصبح رقم الهاتف اختيارياً لحسابات العملاء، لكنه مطلوب للتواصل عند تسجيل مقدم خدمة.
6. فعّل موفر البريد الإلكتروني في إعدادات Authentication. لا يحتاج تسجيل الدخول بالبريد إلى Twilio أو مزود SMS.
7. لإضافة تسجيل الدخول بواسطة Google، أنشئ OAuth Client ID من نوع Web application في Google Cloud Console، واضبط عنوان إعادة التوجيه لديه على
   `https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback`. أدخل Client ID وClient Secret في إعداد موفر Google داخل Supabase.
   في Authentication URL Configuration، أضف عنوان التطبيق `com.munasbh.booking_manager://login-callback/` إلى Redirect URLs.
   لتشغيل الويب محلياً، أضف أيضاً أصل localhost الذي يستخدمه Flutter. لا تضع Client Secret في التطبيق أو المستودع.
8. شغّل التطبيق بإعدادات البناء التالية، مع استخدام مفتاح `anon` العام فقط:

   ```shell
   flutter run --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_ANON_KEY=YOUR_ANON_KEY
   ```

   ويمكن استخدام الوسيطين نفسيهما مع `flutter build web`. لا تضع `service_role` أو أسراراً إدارية في التطبيق أو المستودع.

عند غياب إعداد Supabase يبقى التطبيق في وضع تجريبي محلي. في الوضع السحابي، لا تُنشأ الحجوزات إلا لمقدم خدمة معتمد، ويعيد الخادم حساب السعر والعربون ويتحقق من التوفر بدلاً من الوثوق بالسعر المرسل من العميل.

## حدود النسخة

لا تتضمن النسخة الحالية دفعاً إلكترونياً، أو محادثات مباشرة، أو إشعارات دفعية، أو رفعاً حقيقياً لمعرض صور المزودين. يلزم إعداد مشروع Supabase وخدمة البريد الإلكتروني، ومراجعة سياسات الخصوصية والإلغاء والاسترداد قبل الإطلاق الفعلي. رقم الهاتف في حساب العميل غير موثق؛ لا تستخدمه للتحقق الأمني أو استعادة الحساب.
