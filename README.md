# مناسبتي

تطبيق Flutter عربي لإدارة حجوزات المناسبات والحركات المالية وبيانات مزودي الخدمة.

## الوظائف الحالية

- واجهة سوق للعملاء بالوضع الداكن والأحمر، مع عروض وفئات الخدمات والبحث والترتيب بالتقييم أو القرب.
- صفحة مقدم خدمة بتصميم ملف اجتماعي، وتقييم وأسعار ومعرض صور/فيديو توضيحي وتقويم يميز الأيام المحجوزة بخط أحمر.
- طلب حجز محلي من ملف مقدم الخدمة، ومتابعته من واجهة العميل أو تأكيده وإلغاؤه من واجهة مقدم الخدمة.
- واجهة رسائل وإشعارات تجريبية، مع إمكانية التبديل بين واجهة العميل ومقدم الخدمة ولوحة الإدارة.
- إنشاء الحجوزات والبحث عنها وتصفيتها حسب الحالة.
- تحديث حالة الحجز وتسجيل دفعات جزئية أو كاملة.
- تسجيل الإيرادات والمصروفات ومراجعة ملخص الحسابات.
- إضافة مزودي الخدمة وإزالتهم.
- استعراض أماكن إقامة تجريبية، اختيار فترة متاحة، وتسعير كل ليلة وفق الموسم.
- متابعة طلب الإقامة وإيصالات التحويل اليدوي وحالة المزود والنزاع والتسوية.
- حفظ البيانات على الجهاز؛ يستخدم التطبيق تخزين المتصفح على الويب وتخزين التطبيق المحلي على الأجهزة المدعومة.
- واجهة عربية متجاوبة للويب وسطح المكتب والهواتف.

## نموذج الشاليهات والدفع

يستخدم النموذج بيانات إقامة توضيحية محلية لا تمثل عروضاً حقيقية. يتحقق من تعارض الفترات باعتبار يوم المغادرة غير مشمول في سعر الليالي، ويحسب العربون الافتراضي 10% والعمولة 2% لكل طلب مع حفظ السياسة التي وافق عليها الطلب. يمكن تعديل نسبة العربون للطلبات الجديدة فقط.

تسجيل الكريمي أو جيب يحفظ مرجع العملية وصورة إيصال بحد أقصى 512 كيلوبايت لمراجعة يدوية محلية؛ لا يوجد تكامل API أو تحويل فعلي. تحفظ الصور ضمن بيانات الجهاز/المتصفح، لذلك يبقى هذا مناسباً للتجربة فقط. تبقى المبالغ المحتجزة مرتبطة بكل طلب، ويُتاح فتح التسوية بعد إتمام الإقامة وانقضاء 24 ساعة دون نزاع. سياسة الإلغاء والاسترداد غير معتمدة، لذلك لا ينفذ النموذج إلغاءً أو استرداداً مالياً تلقائياً. يلزم Backend موثوق وسياسات معتمدة قبل استقبال أموال حقيقية.

## التشغيل

```shell
flutter pub get
flutter run
```

لإنشاء نسخة ويب:

```shell
flutter build web
```

هذا الإصدار نموذج محلي أولي؛ لا يتضمن تسجيل دخول، أو مزامنة بين الأجهزة، أو بوابة دفع، أو رسائل WhatsApp/إشعارات فعلية. بياناته محلية على الجهاز ولا تُعد قاعدة بيانات سحابية أو نظاماً محاسبياً معتمداً.

## واجهات السوق والعملاء ومزودي الخدمة

تبدأ نسخة الهاتف بواجهة العميل، ويمكن تبديل الدور من رمز التبديل أعلى الشاشة؛ واجهة الإدارة الحالية متاحة من الخيار نفسه. عروض وفئات ومعلومات المزودين والوسائط في صفحة الملف أمثلة مرئية وليست ملفات منشورة من حسابات حقيقية. تعرض المسافات والتقييمات والعروض بيانات توضيحية محلية، كما أن الرسائل والإشعارات واجهات فقط.

تُحفظ طلبات الحجز التجريبية في التخزين المحلي وتظهر في الحجوزات الإدارية، ويمكن لمقدم الخدمة تأكيدها أو إلغاؤها. لا يوجد حالياً تسجيل أو تحقق من رقم الهاتف أو ملفات منفصلة للمستخدمين، ولا رفع فعلي لصور وفيديوهات المزود، ولا GPS أو دردشة مباشرة أو إشعارات دفعية. يلزم بناء Backend وتطبيقات/صلاحيات حقيقية ومراجعة سياسات الخصوصية والدفع قبل الإطلاق.
